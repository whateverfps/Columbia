Closed-world rule

Chief has no public-web connector in this prototype. If the answer is not supported by the organizational model, Chief says so instead of filling the gap from the internet.

LAYER 1
System Registry
Start by understanding what already exists, what each system owns, its keys, authority, access path, permissions and freshness.
LAYER 2
Canonical Model
The common enterprise vocabulary. Chief should reason about Project, Client, Company, Person/Role, RFI, Submittal, Schedule Activity and other stable objects—not random filenames.
LAYER 3
System Crosswalk
One real-world object can have different IDs in Procore, ERP, CRM and scheduling. The crosswalk resolves them to one canonical identity.
LAYER 4
Evidence Index
The index does not replace the source. It points to authorized organizational evidence, preserves authority/freshness, and attaches that evidence to known entities.
LAYER 5
Relationship Model
These edges are what let Chief move from a project to an RFI, from an RFI to a drawing, meeting, email, schedule activity, cost context and KPI.
MANUAL TRAVERSAL
Entity Explorer
Pick an entity and manually follow its crosswalk, evidence and relationship neighborhood. This is the easiest way to understand what Chief is doing under the hood.
AUTOMATED TRAVERSAL
Chief — Internal Reasoning Trace
Chief resolves intent against the organizational map, checks identity, traverses relationships, retrieves only authorized evidence, then synthesizes a sourced work product.
